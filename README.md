# proto2arrow

A Rust procedural macro to generate efficient Arrow builders from `prost` structs.

This crate provides a `#[derive_builder]` macro that creates a corresponding Arrow `StructArray`
builder for structs generated by `prost`. This allows you to convert Protobuf data into an Arrow
format without writing boilerplate builder code.

## Example

This guide assumes you already have a project using `prost` and `prost-build`.

First, add `proto2arrow` to your `Cargo.toml`:

```toml
[dependencies]
# Your other dependencies...
proto2arrow = "0.1.0"
arrow = "..." # Make sure this version is compatible with proto2arrow
```

Next, modify your `build.rs` to add the `type_attribute` to your existing `prost_build::Config`:

**`build.rs`**
```rust
fn main() {
    prost_build::Config::new()
        // Add this line to your existing prost-build config
        .type_attribute(".", "#[derive(proto2arrow::derive_builder)]")
        // ...
        .compile_protos(&["src/my_protos.proto"], &["src/"])
        .unwrap();
}
```

This tells `prost` to add `#[derive(proto2arrow::derive_builder)]` to every message it generates.

Now you can use the generated builders in your application code.

**`src/main.rs`**
```rust
use arrow::array::StructArray;

// Include the generated code from `prost`
include!(concat!(env!("OUT_DIR"), "/my.package.name.rs"));

// Assuming your .proto file defines a `User` message.
// The `derive_builder` macro generates a `UserBuilder` struct.
fn main() {
    let mut builder = UserBuilder::default();

    builder.append_value(User {
        name: "Alice".to_string(),
        age: 30,
    });

    let array: StructArray = builder.finish();
    assert_eq!(array.len(), 1);
    println!("Successfully created Arrow array from User structs.");
}
```

## How It Works

The `#[derive_builder]` macro generates a builder struct for each struct it's applied to
(e.g., `User` -> `UserBuilder`). This approach creates builder code for each of your
types at compile time, rather than relying on dynamic dispatch (trait objects).

This design comes with few key trade-offs:

*   **Runtime Performance vs. Compile Time**: The macro generates highly specialized code
for each struct. This gives excellent runtime performance because the compiler can inline
and optimize everything, but it will increase compile times.
*   **Developer Experience vs. Binary Size**: Because concrete builder types are generated,
you get great IDE autocompletion and type safety. The trade-off is that this generated code
can lead to a larger final binary.

## Generated API

The generated builder for a struct `T` (e.g., `User` -> `UserBuilder`) provides the following:

### Builder Methods
*   `TBuilder::default() -> Self`
*   `builder.append_value(&mut self, item: T)`
*   `builder.append_null(&mut self)`
*   `builder.append_option(&mut self, item: Option<T>)`
*   `builder.finish(&mut self) -> StructArray`
*   `builder.finish_cloned(&self) -> StructArray`

### Trait Implementations
*   `impl Debug for TBuilder`
*   `impl Default for TBuilder`
*   `impl Extend<Option<T>> for TBuilder`
*   `impl arrow::array::ArrayBuilder for TBuilder`

## Supported Types

| Protobuf Source | Rust (Prost) Type | Arrow Builder |
|-----------------|-----------|---------------|
| `bool` | `bool` | `BooleanBuilder` |
| `int32`, `sint32`, `sfixed32` | `i32` | `Int32Builder` |
| `int64`, `sint64`, `sfixed64` | `i64` | `Int64Builder` |
| `uint32`, `fixed32` | `u32` | `UInt32Builder` |
| `uint64`, `fixed64` | `u64` | `UInt64Builder` |
| `float` | `f32` | `Float32Builder` |
| `double` | `f64` | `Float64Builder` |
| `string` | `String` | `StringBuilder` |
| `bytes` | `Vec<u8>` | `ListBuilder<UInt8Builder>` |
| `repeated` fields | `Vec<T>` | `ListBuilder<TBuilder>` |
| `optional` fields | `Option<T>` | `TBuilder` with `append_option` |
| `map` fields | `HashMap<K,V>` | `MapBuilder<KBuilder, VBuilder>` |
| `message` types | Custom structs | `{StructName}Builder` |
| `oneof` fields | Custom enums | `{EnumName}Builder` |

## Limitations

*   Structs that refer to each other in a cycle are not supported.
*   The macro is designed for structs generated by `prost` and
may not work on hand-written structs with incompatible types.
*   Fields inside a `Box<T>` are not yet supported.
*   Your project and `proto2arrow` must use compatible versions of the `arrow` crate.
